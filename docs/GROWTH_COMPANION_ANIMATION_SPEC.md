# 潤光角色動態與透明分層規格 v2

> 狀態：正式製作基準
> 適用範圍：12 個成長姿態、培育頁主角色、升級／XP 通知縮圖與離線 fallback
> 本版基準：每個動作循環 **32 張實際美術畫格、3.2 秒、50 fps 成品（160 frames）**

## 1. 目標與不可妥協原則

潤光的動態不是用 CSS 對單張圖做位移、縮放或旋轉。每一個成長姿態都必須像活著的角色，能呈現蓄力、重量、慣性、呼吸、漂浮、方向感與附肢反應。

- 32 格均為實際繪製／生成後人工選定的相鄰姿勢，不得以 8 張大幅跳 pose 冒充 32 格。
- 50 fps 是由 32 張來源畫格在離線製作階段補成 160 格；正式播放端不得用 CSS 補肢體動作。
- 背景、角色、接地陰影與前後景特效必須分層；背景在一個循環內完全固定。
- 身體、核心、手、翼、尾、軌道、漂浮珠與配件屬於同一時間軸，不得各自漂移或像貼紙旋轉。
- 半透明是材質，不是消失。下半身、附著點與外輪廓在任何格都必須清楚存在。
- 12 個姿態各有獨立動作輪廓，不得把同一套 transform profile 套用 12 次。
- 型態轉場是升級慶祝，不得取代角色在該型態中的常駐動態。

## 2. 每階正式交付物

每一個姿態／動作至少交付下列項目：

```text
stage-XX/
  source/
    character-00..31.png       # RGBA、straight alpha、32 張來源畫格
    shadow-00..31.png          # RGBA，可共用較少張但時間軸須對齊
    effects-back-00..31.png    # 選配，角色後方特效
    effects-front-00..31.png   # 選配，角色前方特效
    frame-manifest.json        # 畫布、錨點、格號、時間與版本
  sheets/
    character-sheet-01.png     # frames 00–07，4×2、row-major
    character-sheet-02.png     # frames 08–15
    character-sheet-03.png     # frames 16–23
    character-sheet-04.png     # frames 24–31
  runtime/
    character-50fps.*          # 3.2 秒／160 格透明播放資產
    shadow-50fps.*
    effects-50fps.*            # 選配
    poster.webp                # 靜態與 reduced-motion fallback
  qa/
    contact-sheet.png
    habitat-preview-50fps.mp4
    alpha-on-light.mp4
    alpha-on-dark.mp4
    qa-report.json
```

檔案格式可依瀏覽器支援輸出 WebM alpha、animated WebP 或 sprite/runtime 資產；上述 `source/*.png` 是不可丟棄的 canonical master。MP4 只能做審稿預覽，不得作需要透明合成的正式角色資產。

## 3. 時間軸：32 張來源畫格到 50 fps

### 3.1 固定參數

| 項目 | 規格 |
|---|---:|
| 循環長度 | 3.2 秒 |
| 來源美術畫格 | 32 格 |
| 來源取樣率 | 10 fps |
| 成品播放率 | 50 fps |
| 成品總畫格 | 160 格 |
| 每一來源區間 | 5 個成品取樣點 |

對來源格 `S[i]` 與下一格 `S[(i+1) mod 32]`，成品依序取樣 `t = 0, 0.2, 0.4, 0.6, 0.8`。第 31 格到第 0 格也必須照相同規則補格，因此循環接縫是正式動作的一部分，不是播放端硬切。

### 3.2 補格規則

- 補格在離線資產管線完成；播放端只負責按 50 fps 顯示已核准的成品。
- 色彩轉為 linear RGB 後預乘 alpha，再進行形變／光流補格；完成後才轉回交付格式，避免白邊、黑邊與玻璃顏色污染。
- RGB、alpha、角色 coverage mask、配件 anchor 必須沿同一 motion field 移動。
- 不得以 crossfade 取代形變；同一時刻不得出現兩套核心、雙輪廓或殘影。
- 當相鄰來源格無法可靠補格時，必須補畫來源格，不得提高光流強度硬救。
- 32 張來源格必須能單獨以 10 fps 播放並看出連續動作；50 fps 只負責平滑，不負責創造缺失姿勢。

## 4. 畫格設計與 sheet 邊界

四張 4×2 sheet 均使用相同透明畫布、視角、鏡頭、角色基準尺寸與 row-major 格序。圖內不可有格線、文字、編號或不同背景色；格號由 manifest 管理。

### 4.1 32 格動作弧線範本

實際節奏可依型態調整，但必須涵蓋完整力學：

- `00–03`：中性待機與預備。
- `04–07`：蓄力／壓縮，力量方向清楚。
- `08–11`：釋放與起身。
- `12–15`：上升、扭身或展開。
- `16–19`：最高點／主姿勢與方向反轉。
- `20–23`：下降與末端附肢延遲。
- `24–27`：接觸、壓縮或收勢。
- `28–31`：回彈、回復，為 `31 → 00` 留下連續速度。

### 4.2 必查邊界

`07→08`、`15→16`、`23→24` 是 sheet 交界，`31→00` 是循環交界。四個邊界適用與一般相鄰格完全相同的檢查，不得因換 sheet 出現：

- 鏡頭、角色比例、中心點或色溫改變；
- 核心、星絡、浮珠、翼或配件數量改變；
- 背景色殘留、裁切框或 alpha 硬邊；
- 瞬間換側、附著點斷開或輪廓重畫成另一個角色。

## 5. 固定棲境與正式分層

正式合成順序由後至前固定為：

1. `habitat`：單張固定 RGB 背景；一個循環內像素不得抖動、重生或呼吸。
2. `effects_back`：角色後方光粒、水紋或遠景反光；選配。
3. `shadow`：獨立 RGBA 接地／水面投影。
4. `character`：32 格 RGBA 角色本體，包含所有結構性肢體與核心。
5. `effects_front`：越過角色前方的粒子或光絲；選配。
6. UI：文字、XP 與控制元件，不屬於美術動畫資產。

規則：

- 角色來源內不得烘焙棲境、地面、水面、接地陰影或 UI。
- 背景不得跟著角色的跳躍、扭動、縮放或光流變形。
- 陰影可依角色高度改變尺寸、模糊與濃度，但保持在地面透視平面，不跟著角色旋轉。
- 水面漣漪若會被角色遮擋，拆成 back/front 兩層；不可複製整張水面疊在角色周圍。
- 正式資產禁止從 RGB 合成圖以 soft-matte 臨時去背；該方法只可做概念預覽。

## 6. 透明玻璃材質與 alpha 安全規範

### 6.1 輸出基準

- canonical master 使用 RGBA、straight alpha、sRGB；不得帶白色／黑色 matte。
- 製作與補格期間使用 premultiplied alpha；輸出時依 runtime 格式明確標記 straight 或 premultiplied，兩者不可混用。
- 每格另保留 `body_coverage_mask`、`outer_rim_mask` 與必要的 attachment masks，供補格與自動 QA 使用。
- 透明像素的 RGB 必須完成 edge dilation，避免縮放與雙線性取樣產生白暈。

### 6.2 角色結構最低 alpha

以下門檻以 0–1 alpha 表示，套用於角色本體，不套用於可消散粒子：

| 區域 | 最低 alpha | 說明 |
|---|---:|---|
| 結構性凝膠填充 | `0.42` | 身體內部可透景，但不可露空成缺肢 |
| 外輪廓／下半身承重輪廓 | `0.58` | 跳起與扭身時仍須連續可讀 |
| 翼根、手根、尾根、配件 anchor 周圍 | `0.62` | 防止附肢看似斷裂或漂浮 |
| 核心主體 | `0.78` | 亮度可變，形狀與位置不可消失 |
| 粒子／光霧 | 可低於 `0.42` | 必須放在 effects 層，不得用來補角色輪廓 |

每個補間格都需滿足：

```text
alpha_out >= 0.42 * warped_body_coverage
alpha_out >= 0.58 * warped_outer_rim
alpha_out >= 0.62 * warped_attachment_mask
```

這是最低安全層，不代表整個身體要變成不透明。高光、折射、珍珠膜與內部星光仍可建立透明層次，但不得以刪除 base alpha 換取透明感。

### 6.3 「下半身消失」判退條件

任一條成立即退回修圖：

- 下半身外輪廓中斷超過角色 bounding box 寬度的 3%。
- 同一結構區域的 alpha 在相鄰來源格下降超過 `0.18`，但沒有遮擋或轉身理由。
- 跳起時下半身只剩高光、背景能直接穿成洞，或輪廓與陰影之間出現去背暈邊。
- 在 10% 灰、50% 灰、95% 白及正式棲境上，任一背景使下半身無法於正常播放速度辨識。
- 補格後出現雙層透明身體、核心複影或一格以上的局部蒸發。

## 7. 身分一致性與附肢／配件同步

### 7.1 身分不變項

同一姿態的 32 格與所有補格必須固定：

- 核心數量、核心形狀、主色與角色物種輪廓；
- 眼／臉（若有）、翼、手、尾、鰭、浮珠、軌道與印記的數量；
- 星絡拓樸與主要節點，不得逐格隨機重畫；
- 左右側辨識、前後遮擋關係與光源方向；
- 材質比例：水晶藍身體、暖金核心、珍珠膜與水生生命感。

相鄰來源格的角色 bbox 面積變化不得超過 8%（明確 squash/stretch 格除外）；核心相對身體中心的非設計性漂移不得超過角色高度 2%。

### 7.2 同步規則

- 身體先發動，近端關節跟隨，翼尖／尾尖等末端最後到位。
- 漂浮珠相對身體可延遲 2–4 個「來源格」的相位，但必須沿可追蹤軌跡移動，不能固定在螢幕座標。
- 核心亮度在身體上升中後段達峰，下降時回落；亮度變化不得造成核心邊界消失。
- `crest`、`core`、`left_wing_root`、`right_wing_root`、`tail_root`、`orbit` 等 anchor 必須寫入 manifest。
- anchor 在相鄰來源格的非動作性誤差不得超過角色高度 0.5%；任何格都不得脫離所屬表面。
- rear/front parts 可分層，但必須共用同一格號、同一 motion clock 與同一 attachment anchor。
- 任何手、翼、尾、軌道或配件不得穿過身體、突然換側、增減數量或落後成為獨立貼紙。

## 8. 循環接縫規格

循環必須同時做到 pose、位置、亮度、速度與加速度連續。`31→00` 不得靠複製第 0 格或長時間停格掩飾。

自動／人工門檻：

- `frame 31` 與 `frame 00` 的 bbox 中心距離 ≤ 角色高度 1.5%。
- bbox 面積差 ≤ 3%，核心平均亮度差 ≤ 5%。
- 對齊後的主要 silhouette IoU ≥ 0.90。
- `30→31`、`31→00`、`00→01` 的主體速度方向一致；接縫速度幅度差建議 ≤ 20%。
- 以 0.25×、1×、2× 速度各循環播放 10 次，不得看見頓點、跳位、閃光或背景抽動。
- 若接縫必須承接落地回彈，frame 31 應保留朝 frame 00 的速度，不可在 frame 31 完全停住。

## 9. 共用動作狀態

每個姿態最終至少具備：

1. `idle_primary`：本規格的 3.2 秒／32 來源格／50 fps 無縫循環。
2. `idle_secondary`：低頻觸發、幅度明顯的招牌動作，避免長時間觀看過度機械；不得破壞主循環身分或增減附肢。
3. `xp_react`：0.7–1.0 秒，核心吸收並回復待機。
4. `level_react`：1.2–1.8 秒，姿態展開且附肢完整跟進。
5. `rest`：恢復任務時的安靜動作。
6. `reduced_motion`：靜態 poster；不做輪廓位移、旋轉、彈跳或翼拍。

XP／升級反應結束時需在主循環可銜接的 pose 與速度點返回，不得硬切回 frame 00。

## 10. 十二姿態動作輪廓

| Lv | 型態 | `idle_primary` 動作 | 附肢同步規則 |

| 2 | 光滴・凝核 | **已確認方向：蓄力、明顯躍起、扭身旋轉、落地壓縮與回彈** | 核心、下半身與星點保持完整；落地陰影獨立，透明度不得因上升而降低 |
| 3 | 光滴・浮珠 | 橢圓形漂浮路徑，落點前短暫停頓 | 浮珠繞行角速度隨身體升降微調 |
| 4 | 潤團・萌翼 | 身體上提，雙側嫩翼先收後拍開 | 左右翼略錯相但同一節奏；翼根固定 |
| 5 | 潤團・生環 | 蓄力後螺旋躍起，環軌繞核心保持透視 | **僅有一片右下／右後葉尾**，尾根固定並延遲 2–3 格；環軌與單顆衛星不可獨立漂移 |
| 6 | 潤團・顯紋 | 呼吸時星絡由核心向外亮起 | **僅有一片右葉尾且禁止左附肢**；尾尖在亮度峰值後回彈一次，環軌與單顆衛星同步跟隨 |
| 7 | 流環・展尾 | 前傾游動，頂／側／尾鰭產生波傳 | 波由身體根部依序傳至尾尖，不可同拍硬轉 |

| 9 | 流環・雙鳴 | 左右大翼交替推水，身體做細微反扭 | 翼、身體、尾部形成完整反作用力鏈 |
| 10 | 星潮・化潮 | 大幅但緩慢的漂浮弧線，核心潮汐脈衝 | 多翼分兩組依序展開，漂浮珠延遲跟隨 |
| 11 | 星潮・棲境 | 身體環繞棲境中心做小半徑巡游 | 翼尖與尾尖依路徑曲率調整，環軌保持透視 |
| 12 | 星潮・完全共鳴 | 低頻優雅轉身，翼冠完整舒展後收束 | 所有附肢採根部到末端的連鎖展開；星珠形成一輪共鳴 |

### 10.1 `idle_secondary`：十二階誇張招牌動作

每階第二動作固定為 **32 張實際美術畫格、3.2 秒、10 fps 來源，離線補成 160 格／50 fps**。它必須與同階 `idle_primary` 有清楚不同的主輪廓與力學重音；不得只把主動作加速、鏡像、放大或反播。

| Lv | 招牌動作 | 32 格編舞（每段 8 格） | 附肢／配件同步 |
|---:|---|---|---|
| 1 | **露珠彈弓**：壓成圓餅後斜上彈射，空中拉成長水滴再柔軟落下 | `00–07` 吸氣側傾、壓縮；`08–15` 斜上爆發、拉長；`16–23` 空中反弓、換向；`24–31` 落地扁壓、三次遞減回彈 | 無附肢；核心先滯後追、最高點微超前，外殼與下半身全程連續，不得把核心甩出殼外 |
| 2 | **果凍側輪**：向一側猛壓，沿輪廓做一圈大側滾後急煞立正 | `00–07` 左壓蓄力；`08–15` 側輪加速；`16–23` 最大傾角與超越；`24–31` 反扭煞車、回彈 | 核心相對身體延遲 2 格、星點沿同一形變場流動；不得變成獨立旋轉貼圖，並與主動作的垂直螺旋躍起區隔 |
| 3 | **衛星彈弓**：身體急墜再上衝，單顆浮珠沿大弧被甩到前方並牽回 | `00–07` 浮珠落後、身體下沉；`08–15` 上衝與大弧加速；`16–23` 浮珠超越、身體反傾；`24–31` 弧線收窄、回到中性 | 浮珠只能有一顆，沿可追蹤軌跡延遲 3–4 格；核心與星絡拓樸不變，不得把浮珠瞬移到另一側 |
| 4 | **雙翼火箭拍**：雙葉翼抱身蓄力，猛拍展開使身體垂直衝高，頂點張成英雄姿勢 | `00–07` 雙翼由根部內收；`08–15` 同步猛拍、主體衝高；`16–23` 翼尖超越、寬幅懸停；`24–31` 落下、翼膜波傳收勢 | 固定兩片葉翼；翼根先動、翼尖晚 2 格，左右可錯相 1 格但不得換側、穿殼或長出第三翼 |

### 10.2 第二動作安全範圍、銜接與推出順序

- 誇張來自 **silhouette、squash/stretch、路徑與附肢慣性**，不是鏡頭晃動；habitat、鏡頭與 UI 全程固定。
- 動態 bbox 必須留在角色安全畫布內：四邊至少保留畫布短邊 `8%`，任一格不可裁切翼尖、尾尖、環軌或星珠。相鄰格 bbox 面積變化仍遵守第 7.1 節；設計性 squash/stretch 也不得造成附著根 alpha 低於第 6.2 節門檻。
- 容許最大主體位移以角色中性高度計：Lv1–3 水平 `18%`／垂直 `30%`，Lv4–6 水平 `22%`／垂直 `34%`，Lv7–12 水平 `28%`／垂直 `38%`；超過時擴大角色安全畫布，不可縮小或裁掉附肢補救。
- `frame 00` 與 `frame 31` 都是同一個可銜接中性姿勢，但保留相容速度；除了通過 `31→00` 自循環，也要能從 `idle_primary` 的中性 marker 進入並返回，禁止 crossfade、瞬移或硬切。
- `idle_secondary` 採可重現的低頻排程：首次在 `idle_primary` 完成 8–14 輪後播放，其後每 11–22 輪播放一次；不使用每次 render 隨機抽選。觸碰、XP、升級事件優先，第二動作延後到事件反應完整結束。
- 第二動作只在剩餘 2 輪、畫面可見且正常播放時按需預載；`Save-Data`、`slow-2g`、`2g`、`prefers-reduced-data`、離屏、背景分頁或 Sheet 覆蓋時禁止或取消預載。資產未完整取得 HTTP 200 response 前繼續主循環，不硬切海報，也不把十二階 secondary 全部加入 PWA precache。
- 推出順序採 **Lv1 單階試作 → Lv1–3 → Lv4–6 → Lv7–9 → Lv10–12**。每批只在四個 sheet 邊界、alpha、附肢 anchor、50 fps 補格、手機安全框與十輪無縫播放全部通過後進 manifest；不得用前一階 transform profile 批次套用下一階。

## 11. PWA 與手機效能預算

### 11.1 網路與記憶體

- 首屏先載入 `poster.webp`，單檔目標 ≤ 220 KB；動畫在主內容可互動後載入。
- 單一姿態完整 runtime pack（角色、陰影、必要特效，不含共用棲境）目標 ≤ 3.5 MB，硬上限 5 MB。
- 共用棲境單檔目標 ≤ 700 KB；不得為每格複製背景。
- 同時只常駐目前姿態與必要的下一姿態 poster；不得預載 12 套 50 fps 成品。
- decoded texture／frame buffer 總量目標 ≤ 48 MiB，硬上限 64 MiB；不得把 160 張全尺寸 RGBA 同時解碼常駐。
- 來源 atlas 單邊不超過 4096 px；runtime 顯示用角色畫格建議不超過 1024×1024。

### 11.2 播放與生命週期

- 培育頁主角色目標為穩定 50 fps；測試期間 1% low 不得低於 45 fps。
- 僅允許 1 個完整角色動畫 runtime；通知縮圖出現時，不得同時啟動第二套高解析 runtime。
- 元件離開 viewport、`document.hidden`、Sheet 完全覆蓋或路由離開時立即暫停，回來後從時間軸正確位置恢復。
- 解碼／補格應在建置階段完成；手機端不得執行重型 optical flow。
- `Save-Data`、資產載入失敗或硬體能力不足時使用 poster fallback，不以不穩定的低幀率勉強播放。
- 離線快取目前姿態 runtime、poster、棲境與 manifest；版本更新採 content hash，避免新舊 sheet 混用。

## 12. Reduced motion 與可及性

- `prefers-reduced-motion: reduce` 或 App 內「減少動態」開啟時，預設只顯示 poster。
- reduced-motion 不做彈跳、旋轉、扭身、漂浮或持續縮放；必要狀態提示以文字、圖示與不超過 200 ms 的淡入淡出呈現。
- CSS 可負責顯示／隱藏、播放／暫停與短淡入淡出，不得重新創作角色肢體動作。
- 動畫不是完成任務或理解 XP 變化的唯一管道；所有成就／升級通知都需有可讀文字。

## 13. QA Gate（全部通過才能進入正式 App）

### Gate A：來源與結構

- [ ] 32 張來源格齊全、格號唯一，manifest 與 4 張 sheet 對應正確。
- [ ] 角色為原生 RGBA，沒有 RGB soft-matte 去背、背景殘色、白邊或烘焙陰影。
- [ ] 背景、陰影、角色、前後景特效可獨立關閉檢查。
- [ ] 角色身分、星絡拓樸、附肢／配件數量與 anchor 全程一致。

### Gate B：透明與逐格

- [ ] 自動 alpha-floor 檢查通過，尤其是下半身、外輪廓與附著點。
- [ ] 32 格 contact sheet 人工逐格檢查，沒有缺肢、穿模、換側、增生或局部蒸發。
- [ ] 合成於黑、白、10%／50% 灰與正式棲境皆可辨識完整角色。
- [ ] 50 fps 補格沒有雙核心、雙輪廓、透明殘影或光流融化。

### Gate C：動作與循環

- [ ] 10 fps 來源版已具連續性；50 fps 版只增加平滑度。
- [ ] `07→08`、`15→16`、`23→24`、`31→00` 四個邊界逐格通過。
- [ ] 3.2 秒／160 格／50 fps 媒體資訊正確，循環 10 次無可見接縫。
- [ ] 身體、核心、手、翼、尾、軌道、浮珠、印記與配件共享同一力學節奏。
- [ ] 固定棲境沒有抖動，陰影高度反應正確且未跟角色旋轉。

### Gate D：真機與 PWA

- [ ] 320／390／430 px 手機不裁角色、不出現橫向捲動或 UI 遮擋。
- [ ] Light／Dark、背景切換、鎖屏恢復、路由切換與離線 fallback 均通過。
- [ ] iOS Safari PWA 與 Android Chrome PWA 各完成至少一次真機錄影。
- [ ] 主角色穩定 50 fps、1% low ≥ 45 fps，且符合網路與記憶體預算。
- [ ] reduced-motion、Save-Data、離開 viewport 與 document hidden 行為正確。

未通過任一 Gate 的資產只能留在 concept／preview，不得寫入正式 animation manifest。
